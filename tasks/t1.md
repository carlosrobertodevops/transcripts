## Categoria: Server Actions (CRUD)

- [ ] Criar `src/actions/operacoes.ts` com Server Actions usando `'use server'` para mutações e consultas do MVP
- [ ] `criarOperacao(formData)` — cria operação com `nome`, `responsavel` e `dataOperacao` validada; upload de mídia fica em action separada para manter fluxo transacional claro
- [ ] `editarOperacao(id, formData)` — atualiza `nome`, `responsavel` e `dataOperacao`
- [ ] `deletarOperacao(id)` — primeiro executa transação no PostgreSQL/Drizzle removendo a operação e usando cascade para remover registros `MidiaUpload` associados
- [ ] `deletarOperacao(id)` — somente depois da transação DB bem-sucedida, remove em modo best-effort a pasta `public/uploads/operacoes/<operacaoId>/`
- [ ] `deletarOperacao(id)` — se a remoção física falhar, registra ou reporta a falha para limpeza manual, sem reverter o DB nem deixar o DB inconsistente
- [ ] `listarOperacoes()` — lista operações com ordenação única: `dataOperacao DESC`, depois `createdAt DESC` como desempate
- [ ] `obterOperacao(id)` — busca detalhes da operação com uploads de mídia relacionados
- [ ] `listarMidiasDaOperacao(operacaoId)` — lista mídias da operação com ordenação única por `createdAt DESC`
- [ ] `adicionarMidiaUpload(operacaoId, formData)` — recebe `FormData`, valida arquivo com Zod 4, grava binário em `public/uploads/operacoes/<operacaoId>/` e depois cria registro `MidiaUpload` via Drizzle
- [ ] `adicionarMidiaUpload(operacaoId, formData)` — persiste no PostgreSQL somente metadados: `operacaoId`, `nomeArquivo`, `tipoMime`, `tamanhoBytes`, `urlArquivo`, `dataUpload` e timestamps
- [ ] `removerMidiaUpload(id)` — primeiro busca o registro e guarda `urlArquivo` e o path físico derivado
- [ ] `removerMidiaUpload(id)` — em transação, remove o registro `MidiaUpload` do PostgreSQL/Drizzle
- [ ] `removerMidiaUpload(id)` — somente depois da transação DB bem-sucedida, remove o arquivo físico em modo best-effort
- [ ] `removerMidiaUpload(id)` — se o arquivo físico não existir, trata como sucesso idempotente e registra aviso
- [ ] `removerMidiaUpload(id)` — se `urlArquivo` for inválida ou o path derivado ficar fora de `public/uploads/operacoes/`, não tenta apagar arquivo físico, registra erro de integridade com `midiaUploadId` e `urlArquivo`, remove o registro do DB em transação porque a fonte de verdade do MVP é o PostgreSQL e bloqueia limpeza física insegura
- [ ] `removerMidiaUpload(id)` — após remover o registro, inclusive no caso de `urlArquivo` inválida ou path fora de `public/uploads/operacoes/`, revalida os paths afetados com `revalidatePath()`
- [ ] Revalidar rotas com `revalidatePath()` após mutações que alterem a página principal ou detalhes da operação

## Categoria: Validação com Zod 4

- [ ] Criar `src/schemas/operacao.ts` com schemas de validação para formulários de operação usando Zod 4
- [ ] Validar `nome` da operação como texto obrigatório com 2 a 120 caracteres
- [ ] Validar `responsavel` como texto obrigatório com 2 a 100 caracteres
- [ ] Validar `dataOperacao` como string no formato `YYYY-MM-DD` recebido de input HTML `date`
- [ ] Normalizar `dataOperacao` validada para `Date` antes de persistir no PostgreSQL
- [ ] Validar upload com arquivo obrigatório via Zod 4
- [ ] Validar upload com tamanho máximo de 500MB
- [ ] Validar upload com MIME allowlist: `audio/mpeg`, `audio/wav`, `audio/mp4`, `audio/x-m4a`, `video/mp4`, `video/webm`, `video/quicktime`
- [ ] Gerar `nomeArquivoSanitizado` removendo path separators, normalizando espaços para hífen, preservando extensão permitida e prefixando timestamp ou UUID curto para evitar colisão
- [ ] Gerar `urlArquivo` pública no formato `/uploads/operacoes/<operacaoId>/<nomeArquivoSanitizado>` após gravar o arquivo no filesystem local
- [ ] Retornar mensagens de erro em pt-BR para Server Actions e forms
